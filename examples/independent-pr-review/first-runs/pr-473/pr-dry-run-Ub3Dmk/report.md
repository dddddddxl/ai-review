### [P2] 停滞上限会提交刚开始的不完整字符

- 位置：python/sglang/srt/managers/detokenizer\_manager.py（行号未确定）
- 触发条件：字节回退 tokenizer 在流式步骤中先连续收到 8 个 0x80，再分步收到字符中的 E4、B8、AD 字节。
- 证据与影响：第 9 步只有 E4，最近边界均以替换字符结尾，阈值分支却提交整个 new\_text 并将 read\_offset 推到 E4 后。B8、AD 补齐后，read\_text 与 surr\_text 都长 9，按上下文长度切片得到空串，无法恢复中。停滞时长不能证明新到的尾字节已完整。 有效多字节字符被永久替换为 U+FFFD，流式输出及最终已提交文本发生内容损坏；旧路径保留偏移直到字节补齐。
- 修改建议：达到上限时也保留仍可能未完成的 UTF-8 尾部，只提交确定稳定的前缀；增加连续替换字节后紧接分步多字节字符的回归用例。

### [P2] 不完整字符测试一次发送了全部字节

- 位置：test/registered/unit/managers/test\_detokenizer\_incremental.py（行号未确定）
- 触发条件：增量解码错误地提交不完整 UTF-8 字符，或连续停滞计数未在干净步骤复位时。
- 证据与影响：\_stream 每个 chunk 只调用一次解码；\[list\(CJK\_BYTES\)\] 将完整字符一次送入，复位测试也每次发送完整的中加 a，两者没有任何不完整字符步骤。错误地每步提交或不复位计数仍可满足现有断言。 所声明的保留不完整字符与停滞计数复位回归保护实际未生效。
- 修改建议：把 CJK 各字节分成独立 chunk，断言前两步不输出替换字符、第三步输出中；复位用例重复交错这些停滞与干净步骤。

### [P2] 干净边界用例没有进入回溯提交分支

- 位置：test/registered/unit/managers/test\_detokenizer\_incremental.py（行号未确定）
- 触发条件：\_find\_clean\_commit 失效或始终返回 None 时。
- 证据与影响：steps 的每项为 \[STRAY\_BYTE, TEXT\_TOKEN\]，伪 tokenizer 解码后以 a 结尾，因此每次都走普通干净文本提交；该测试不会验证其描述的末尾 U+FFFD 回溯提交，现有文本断言也不能区分该分支是否工作。 回溯提交这一新增核心路径退化时该回归测试仍可通过。
- 修改建议：使用末尾为 STRAY\_BYTE、此前存在干净 token 边界的 chunk，并逐步断言已提交偏移和即时输出，避免仅检查最终拼接文本。
