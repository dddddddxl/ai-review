# 1031 候选版交付与上线操作清单

本清单用于准备交付，不是部署授权。用户明确要求本轮不上线；不得因为测试通过或代码已推送就启动生产服务、修改 App Webhook 或合并测试 PR。

## 1. 已具备的工程保护

- `npm test` 默认拦截外部网络。真实模型回放是独立、显式执行的命令，不混入单元测试。
- 生成候选与最终复核分离；固定源码引用未通过核验或仍有未核实前提时，不采纳模型的确认/否决，保留为未知。
- 新增装饰器的固定版本定义通过有界静态提示提供，不执行被审代码。提示不是完整调用图，也不是自动判错。
- 跨批次发现可保留在本 PR 选中文件范围内，不把读取关联文件计为完成另一个批次。
- Native 行内定位需要唯一、可核对的固定源码引用及当前 diff 行；无法唯一定位时进入总结。
- 公开概览仅展示程序生成的变更事实，生成阶段的候选措辞不再越过复核进入公开概览。
- 同进程重复发评互斥；同进程内最多保留 1024 个 Webhook 投递 ID 的去重记录。不是分布式 exactly-once；重启后的发布幂等仍依靠远端审查标记。
- Webhook 签名、仓库白名单、草稿过滤、安装/提交身份通过本地真实签名校验器测试。
- 停机时停止新任务接收与领取，等待在途调度及任务收尾。没有新增隐藏退出超时；若外部容器管理器强杀，下次启动从持久化状态恢复。
- `/ready` 在模型未配置或排空中返回 503；200 仅表示配置/进程就绪，不代表模型质量、外部 API 健康或上线验收通过。

## 2. 候选包核验

1. 固定验收提交、`package-lock.json` 哈希和候选源码包哈希，不直接跟随浮动分支部署。
2. 在独立目录执行 `npm ci --ignore-scripts --no-audit --no-fund`，随后 `npm test`。已有缓存时可使用 `--offline` 复现；缓存不全时失败不能当成测试通过。
3. 通过运行记录核对真实模型版本、固定 base/head、源码指纹、首次失败、复核未知和实际发评链接。
4. 单文件合成样例、历史已知缺陷、真实业务样本分别统计。没有人工裁定的标签集，不宣传准确率或全仓召回率。
5. `partial=true` 不能算完整样本；未知不等于无问题。允许输出有证据的局部结论，但必须显式展示未完成范围。

## 3. 正式部署前仍需操作者提供并确认

| 项目 | 必须满足的条件 |
|---|---|
| 质量放行 | 维护者复核已知正例、干净对照及未参与调优的业务样本，明确可接受的未知率、误报和时延；不能只看 HTTP 成功 |
| 凭据 | 轮换聊天中暴露的模型密钥，旧 key 失效；密钥由私有文件或密钥管理注入，不发聊天、不进 Git |
| App | 安装范围与最小权限经确认；配置 Webhook secret，外部 HTTPS 路由通过实际投递验证 |
| 仓库范围 | 显式设置 `ALLOWED_REPOSITORIES`；先单个获准仓库，不以 App 安装范围代替服务白名单 |
| 模型连接 | 固定模型/协议/推理与预算配置；生产使用 HTTPS 或另行审定的加密隧道 |
| 状态与面板 | `AI_REVIEW_STATE_DIR` 使用独立持久化卷；`AI_DASHBOARD_TOKEN` 独立设置，核验权限和备份 |
| 实例数量 | 先一个服务实例；不能把当前进程内锁当多副本锁 |
| 停机与回滚 | 外部停机宽限期与现有最长审查预算协调；保留真正的上一生产镜像、配置和状态快照 |
| 精确依赖 | 若需判断上游框架语义，提供对应版本源码与身份；拿不到就保留未知，不借用其他版本 |

只读配置检查：

```sh
node --env-file=/secure/reviewer.env scripts/preflight.mjs
```

退出码非零需处理。即使退出码为零，也必须完成质量和运维人工门槛。不得用实测配置冒充正式部署配置。

## 4. 获得单独上线授权后的顺序

1. 记录旧生产镜像摘要、配置版本、App 路由、仓库白名单、队列与状态快照；所有备份留在私有位置。
2. 在隔离副本验证恢复，检查队列、已完成标记和待复核候选可读取；不要覆盖生产目录。本轮只完成了本地合成状态的复制恢复，不代表生产存储已验收。
3. 启动固定候选版本，核对 `/health`、`/ready`、面板鉴权、日志脱敏和依赖连接；不要把进程探针当质量认证。
4. 使用获准测试 PR 验证真实外部 Webhook → 队列 → 模型 → 发评的整条链。此前手动调用发布函数的检查不能替代这一步。
5. 小范围灰度，分别观察排队时长、模型耗时、完整率、未知率、误报、请求/token 数；不同时引入新测试覆盖审查或修改并发、超时、既有 CI 分析策略。
6. 异常时停止新流量并排空任务，保存故障日志和当前状态。恢复已知生产镜像及其兼容配置；新旧状态格式未验证兼容时，使用各自的快照，不让旧代码直接消费未知格式。

## 5. 本轮边界

不部署、不改生产配置、不合并 `quality-gate #17`、不执行目标仓库代码、不占卡。该专用草稿 PR 的自带 CI 和明确标注的测试评论已获授权；业务 PR 只读回放。运行工件与私有配置不推送公开仓库。
