## 4. 失败诊断与离线修正

16 次模型调用中，4 次返回合法的 `action=tools`，11 次超时，1 次没有可接受的完整响应；没有任何可用的 `action=final`。合法 JSON 或取证请求不等于审查完成。约 150 秒停止是主审加增量耗尽、没有最终分析可校验的结果，不是等待到 180 秒才能结束。

### 模型响应仍是主要阻塞

首个取证响应耗时较长，剩余窗口不足以取证后形成、复核和校验最终结论。当前没有验证该网关对 Kimi 关闭思考或其他加速参数的兼容性，不能凭猜测改变参数并宣称有效。#475 的 `incomplete_response` 原始记录没有足够细分原因；不能仅据 token 数量判断具体为空响应、截断或拒答。新版已补充安全诊断字段，等待后续获准实测。

### 宿主取证问题已离线修正

- #477：原定向 `path` 被搜索器忽略，扩大至目录前 100 个文件。已改为精确文件检索，固定 Git 对象批量 grep，敏感/超大/符号链接对象在检索前排除。
- #467：范围搜索原来逐文件启动大小与内容读取进程，约 206 次物理执行、约 18 秒累计 Git 耗时。改为批量搜索并显式分页；首批未命中仍为未知，不推断全仓不存在。
- #473：请求 253–560 共 308 行，超过每次 200 行限制。仍明确拒绝并返回合法范围，不自动裁剪后冒充完整读取；模型当轮未及时纠正。
- 缩短必要源码预读至最多 80 行；仅投递固定 skill 的 PR 模式指令，不加入分支模式内容或历史示例；原校验标准不降低。
- 调度槽释放即推进下一批；首个 Python 校验启动后，共享最多 30 秒且不超过全局剩余时间。
- 保留初次失败；仅同版本、对应范围的真实补读才能解除相关阻塞。未取得测试分析时补充未完成诊断，代码和测试状态独立保留。

原始工具请求离线回放：10 个请求中 9 个正常返回，#473 的越限请求保持拒绝。#477 精确文件搜索约 122 ms、1 个文件、2 个匹配、无截断；#467 范围首批约 120 ms、100 个文件、0 匹配且标记截断。这里是工具级回放时间，不是修正后整个 PR 耗时，也不证明模型分析质量改善。
