# 1031 上线前检查与回滚

本分支是候选代码，不因推送自动上线。先检查本轮真实回放报告，再决定灰度。

## 配置检查

通过服务端私有配置提供凭据，不复制聊天记录中的密钥：

```sh
node --env-file=/secure/reviewer.env scripts/preflight.mjs
```

命令只读检查，不启动服务、不调用模型或 GitHub。退出码 2 表示配置不满足检查项；即使退出码 0，也不表示真实审查质量和上线验收通过。

- 轮换曾暴露在聊天中的模型 API key，确认旧 key 失效。App 私钥如曾泄露正文，也必须轮换；仅提供过本机路径不等于私钥正文已公开。
- 配置 `GITHUB_WEBHOOK_SECRET`；通过 HTTPS 接入 Webhook，验证签名与重复事件处理。
- 明确设置 `ALLOWED_REPOSITORIES`，首轮仅包含维护者批准的测试仓库。安装 App 到全部仓库不代表允许全部接入。
- 明确设置 `AI_PR_REVIEW_ENGINE=evidence-v1` 或经过验收的 `legacy`。当前原生取证需要 `openai-chat`；其他协议不要未经验证启用该路径。
- 配置 `AI_REVIEW_STATE_DIR` 的持久化卷、独立权限、备份和恢复；配置 `AI_DASHBOARD_TOKEN`。
- 生产模型端点使用 HTTPS，或另行审定加密隧道；获准使用 HTTP 做本机测试不能替代生产安全验收。
- 当前发布互斥只覆盖同一进程。使用一个服务实例管理同一队列；不得直接扩成多副本。
- 不随本次发布静默调整模型并发、worker、超时或原有 CI 分析开关。

## 只读真实回放

```sh
# OUTPUT 必须是新目录。当前 PR 源码/diff 冻结后再调用模型，不读取旧评论作为答案。
node scripts/quick-compare.mjs capture OUTPUT --current --repository OWNER/REPO --prs 315,317
node scripts/quick-compare.mjs run OUTPUT fixed --pr 315
# 同一输入，对比原 1027 基线；该基线不是最早 9d8ed71 的生产版本。
node scripts/quick-compare.mjs run OUTPUT baseline /path/to/8ee0769 --pr 315
```

每次调用保存模型次数、token、耗时、输出与失败；`execution.json` 保存输入、源文件和执行器指纹。`tool-deltas.jsonl` 仅保存索引、长度和哈希，不保存原始推理、请求头或工具参数值。首次失败工件不可覆盖。

样本使用全新模型消息，但不是人工认证的盲测。将模型确认、静态可确认、未知和误报分开裁定；没有人工标签集不得宣传准确率/全仓召回率。

## 兼容网关的工具协议

默认 `AI_TOOL_TRANSPORT=native` 保留原生函数调用。可显式设置 `AI_TOOL_TRANSPORT=json` 做对照：模型用最终 JSON 返回工具请求，宿主仍执行相同的工具名、参数 schema、重复字段、路径、固定 SHA 和预算检查。此模式不执行自由文本命令，不改变发布逻辑；缓存按协议隔离。未经真实对照验收不自动切换生产默认。

原生模式若在最终正文返回完整终结 JSON，也仅在同一终结 schema 校验通过后接收，并标记 `terminal_text_fallback`；散文、代码围栏、重复字段或文本工具请求不走此兼容路径。缺证据的结果仍不完整。`reviewPending` 保存未通过复核的候选，不等于已确认或已被否决。

## 灰度与发布保护

1. 先只读回放：运行 `npm test` 和模型对照，确认完整流程、未知状态与资源消耗。
2. 维护者明确批准测试仓库/PR 后，再进行真实评论测试。检查固定 head、定位、敏感信息过滤、重复事件、重试、进度清理。
3. 保存旧镜像摘要、旧配置版本、队列/状态备份；记录新提交和依赖锁文件。用专用副本演练恢复，不覆盖生产状态。
4. 首轮少量仓库，只用代码审查，不新增测试覆盖审查；观察完整率、误报、排队时长、模型调用和 token。没有价格表不推算费用。
5. 若异常：暂停接收/消费新任务，等待或安全终止当前调用；保留新状态和日志，再恢复旧镜像及兼容配置。未经兼容验证不要用旧代码直接消费新状态。

本轮不部署、不修改 App 权限、不轮换用户凭据、不向业务 PR 发评论，也不执行目标仓库代码。
